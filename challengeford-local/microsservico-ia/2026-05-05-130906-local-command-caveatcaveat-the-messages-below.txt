     Plano: Pipeline de Extração de Dados — Projeto Ford Catálogos

     Contexto

     POC de análise competitiva de catálogos automotivos para a Ford Brasil. O
     foco desta sessão é o pipeline de extração: tudo o que o microsserviço
     Python precisa para coletar, extrair e normalizar specs dos 6 catálogos de
     pickups, usando RAG + LLM com geração baseada em evidências.

     A API FastAPI, o Java e o Docker ficam para depois. O objetivo agora é ter
     um script funcional que, dado um catálogo, retorna o schema preenchido com
     metadados de rastreabilidade.

     ---
     Arquivos a Criar (em ordem de dependência)

     microsservico-ia/
     ├── src/
     │   ├── schema.py                    # [1] Pydantic v2 — contrato central
     │   ├── config.py                    # variáveis de ambiente (.env)
     │   ├── llm_client.py               # [2] Claude (primário) + OpenAI
     (fallback)
     │   ├── knowledge_base/

     │   │   └── kb_manager.py           # [3] ChromaDB — 4 coleções

     complemento

     ---
     Detalhe de Cada Arquivo

     [1] schema.py

     - CatalogoSchema (Pydantic v2): ~50 atributos em 7 grupos com tipos
     estritos, enums e ranges via Field
     - AtributoMeta: metadados de rastreabilidade por atributo (confiança,
     fonte, mercado BR, divergente)
     - FonteSecundaria, CatalogoCompleto, TermoDesconhecido, ResultadoExtracao
     - RANGES_SEGMENTO: dict de ranges hard-coded para validação pós-LLM
     - ATRIBUTOS_CORE: set dos 14 atributos obrigatórios que disparam gap-fill

     [2] llm_client.py

     - Protocol LLMClient com método extrair(texto, schema_fields, contexto_rag)
      -> dict
     - OpenAIClient: openai SDK, model configurável via env (gpt-4.1-mini
     padrão), response_format JSON schema, retry com backoff exponencial
     - Lógica de fallback automático: se mini retorna cobertura < 70% ou falha
     de parsing, re-tenta com gpt-4.1
     - get_llm_client(): lê LLM_PROVIDER e OPENAI_MODEL do env, retorna
     instância correta

     [3] kb_manager.py

     - ChromaDB local em data/chromadb/, embedding all-MiniLM-L6-v2
     - 4 coleções: specs_normalizados, terminologia, ranges_segmento,
     capability_definitions
     - inicializar(): cria coleções + carrega seed se vazias
     - buscar_specs_similares(), buscar_terminologia(), buscar_ranges()
     - adicionar_catalogo_validado(): vetoriza atributos com confiança ≥ 0.7 e
     mercado BR
     - construir_contexto_rag(): monta string de contexto para o prompt do LLM
     - Terminology map seed: ~30 termos (4MOTION, Crawl Control, Safety Shield
     360°, etc.)

     [4] pdf_extractor.py

     - download_pdf(): baixa PDFs dos CDNs das montadoras, cache 30 dias
       - Ford, Toyota, VW: URLs confirmadas; Chevrolet, Mitsubishi, Nissan:
     retorna None
     - extrair_specs(): pdfplumber → detecta tabular vs. texto → chama LLM + RAG
     - Cache de hash SHA-256 para detecção de mudanças
     - Tratamento: PDF corrompido, protegido, timeout

     [5] site_scraper.py

     - Playwright async, delay 1–3s humanizado, user-agent realista
     - Scrapers por montadora: Ford, Toyota, VW, Chevrolet, Mitsubishi
     (primária), Nissan (primária)
     - Retorna texto bruto estruturado por seção (LLM extrai valores no agente)
     - Cache HTML 24h em data/raw/
     - ScraperBloqueadoError para 403/CAPTCHA

     [6] fipe_api.py

     - APIs: fipe.parallelum.com.br (primária) + deividfortuna.github.io/fipe
     (fallback)
     - Cache SQLite 7 dias
     - Normalização de preço: "R$ 469.990,00" → 469990
     - Validação de range: R$ 80k–R$ 1.5M
     - FipeResultado dataclass

     [7] agent.py — Orquestrador ReAct

     Loop de 7 passos para cada catálogo:
     1. Percepção: inicializa schema, consulta KB (RAG)
     2. Coleta PDF: download + extração se disponível
     3. Coleta Site: sempre executa (complementa ou substitui PDF)
     4. Coleta FIPE: preço de referência
     5. Resolução de conflitos: PDF vs. site, regra da fonte oficial
     6. Extração LLM + RAG: normaliza via terminology map, detecta termos
     desconhecidos
     7. Validação pós-LLM: ranges, cross-checks, calcula cobertura_pct
     8. Enriquecimento KB: se cobertura ≥ 70%, adiciona ao ChromaDB
     9. Resultado: monta ResultadoExtracao com gaps e log de decisões

     [scripts] 01_seed_kb.py

     - Carrega os 3 JSONs seed de data/seed/
     - Popula as 4 coleções ChromaDB
     - Imprime contagem de documentos por coleção

     ---
     Decisões de Implementação

     - LLM primário: gpt-4.1-mini (OpenAI) via openai SDK, structured output com
      response_format JSON schema
     - LLM fallback: gpt-4.1 (OpenAI) — ativado automaticamente se mini retornar
      cobertura < 70% ou erro de parsing
     - Env: LLM_PROVIDER=openai, OPENAI_MODEL=gpt-4.1-mini,
     OPENAI_MODEL_FALLBACK=gpt-4.1
     - Structured output: OpenAI response_format com JSON schema gerado do
     CatalogoSchema Pydantic
     - null vs. false: atributo bool ausente = None, não False
     - mercado_confirmado_br: True apenas se fonte for domínio .com.br ou PDF
     CDN BR
     - Conflito >5%: valor numérico do PDF prevalece + divergente=True
     - Gap-fill: YouTube/Whisper está na arquitetura mas não implementado agora
     (retorna None com log)

  ---
  Campos que o PDF precisa cobrir (por grupo)

  Motorização
  - Combustível (diesel / gasolina / flex)
  - Cilindrada (ex: 3.0L, 2.8L)
  - Configuração do motor (ex: "V6 biturbo", "4 cilindros em linha")
  - Indução (turbo / biturbo / aspirado)
  - Potência em cv
  - Torque em Nm (ou kgf.m — o LLM converte)
  - Consumo cidade e estrada em km/l

  Transmissão & Tração
  - Tipo de câmbio (manual / automático)
  - Número de marchas
  - Tração (4x2 / 4x4 / 4x4 integral / AWD)
  - Caixa de redução (sim/não)
  - Diferencial com bloqueio (sim/não)

  Dimensões
  - Comprimento, largura, altura (em mm)
  - Entre-eixos (mm)
  - Peso bruto (kg)
  - Capacidade de carga (kg)
  - Capacidade de reboque (kg)

  Off-Road
  - Modos de condução (ex: Eco, Normal, Sport, Off-Road, Rock)
  - Controle de descida (sim/não — pode aparecer como DAC, HDC, Trail Control,
  etc.)
  - Ângulo de ataque (graus)
  - Ângulo de saída (graus)
  - Ângulo de rampa (graus)
  - Profundidade de vadear (mm)

  Segurança & ADAS
  - Quantidade de airbags
  - Frenagem autônoma de emergência (sim/não)
  - Aviso de colisão frontal (sim/não)
  - Manutenção de faixa (sim/não)
  - Monitoramento de ponto cego (sim/não)
  - Câmera de ré (sim/não)
  - Câmera 360° (sim/não)
  - Controle de cruzeiro adaptativo (sim/não)
  - Estacionamento automático (sim/não)

  Conforto & Conectividade
  - Tamanho da tela central (polegadas)
  - Tamanho do painel digital (polegadas)
  - Apple CarPlay (sim/não)
  - Android Auto (sim/não)
  - Conexão sem fio para CarPlay/Android Auto (sim/não)
  - Teto solar (nenhum / escotilha / panorâmico)
  - Material dos bancos (tecido / couro sintético / couro)
  - Bancos elétricos (sim/não)
  - Bancos aquecidos (sim/não)
  - Bancos ventilados (sim/não)
  - Ar-condicionado (simples / digital / dual zone / tri zone)
  - Carregador wireless (sim/não)

  Preço
  - Preço de tabela em R$ (se disponível — caso contrário o agente busca na
  FIPE)

  ---
  Formato ideal

  O LLM extrai bem dos dois formatos — o agente detecta automaticamente qual é:

  - Tabular (Toyota, VW): tabela com "Atributo | Valor" — cobertura ~95%,
  extração mais precisa
  - Texto narrativo (Ford): parágrafos descritivos com specs embutidos —
  cobertura ~85%, funciona bem

  O que não funciona:
  - PDFs com specs como imagem (o texto não é selecionável)
  - PDFs de marketing puro sem dados técnicos
  - PDFs com DRM/senha
